# CLand-LLM

## 项目概述

CLand-LLM 是一个基于 LoRA（Low-Rank Adaptation）技术的大语言模型微调工具包，主要用于对 Llama3.1-8B-Instruct 模型进行高效微调。项目支持多种硬件平台，包括 NVIDIA GPU、国产 DCU 加速卡以及 CPU 训练模式，能够满足不同计算环境下的模型微调需求。

本项目提供了一套完整的 LLM 微调解决方案，涵盖数据准备、模型训练、效果验证等核心功能。通过 LoRA 高效微调技术，用户只需训练少量参数即可实现模型的领域适配和任务优化，大幅降低了显存需求和训练时间。项目的设计充分考虑了易用性和实用性，提供了清晰的目录结构、完善的中文文档说明以及详细注释的训练脚本，帮助用户快速上手并完成模型微调任务。

## 基础工作流

```
数据（单轮指令） → 训练 → 验证：评估模型是否能够正确理解指令并生成合理回复
数据（多轮对话） → 训练 → 验证：评估模型是否能够记住之前对话内容并保持上下文连贯性
```

上述工作流说明了本项目的两种主要训练场景。单轮对话训练主要评估模型对指令的理解能力，模型需要根据给定的指令生成正确的响应；多轮对话训练则着重评估模型的上下文记忆能力，模型需要在理解对话历史的基础上生成连贯的回复。两种训练场景的数据格式和评估指标有所不同，用户可以根据实际需求选择合适的训练模式。

## 核心功能

本项目提供了丰富的功能特性，能够满足不同场景下的模型微调需求。以下是主要功能的详细说明：

### 多硬件平台支持

项目支持三种不同的训练模式，分别是 GPU 训练模式、DCU 训练模式和 CPU 训练模式。GPU 训练模式针对 NVIDIA 系列显卡进行了优化，能够充分利用 CUDA 架构的并行计算能力，实现高效的模型训练。DCU 训练模式专门适配了国产异构加速卡，采用了国产卡专用的 DTK 驱动和 torch-dcu 运行时，确保在国产计算平台上稳定运行。CPU 训练模式作为兜底方案，当没有 GPU 或 DCU 可用时，仍能完成基本的微调任务，虽然训练速度较慢，但能够验证数据流程和模型配置的正确性。

### LoRA 高效微调

项目采用 LoRA（Low-Rank Adaptation）技术进行模型微调，这是当前最受关注的高效微调方法之一。LoRA 的核心思想是在预训练模型的权重矩阵旁边添加低秩矩阵，通过训练这些低秩矩阵来实现对模型行为的调整，而不需要修改原始模型的权重。这种方法的可训练参数通常只有原始模型参数量的千分之一甚至万分之一，大大降低了显存需求和训练时间。项目中 LoRA 的关键参数包括秩（r）、缩放系数（lora_alpha）、dropout 概率（lora_dropout）以及目标模块（target_modules），用户可以根据实际需求进行调整。

### 单轮对话训练

单轮对话是最基本的对话形式，用户发送一条指令或问题，模型给出一次回复。本项目支持指令-响应（Instruction-Response）格式的训练数据，训练数据中包含 instruction 字段和 response 字段，分别表示输入指令和期望的输出回复。在训练过程中，系统会将指令和回复拼接成统一的文本格式，然后进行 tokenization 和标签生成。这种训练方式适用于问答系统、任务指令执行、知识问答等场景，能够有效提升模型对特定类型指令的理解和响应能力。

### 多轮对话训练

多轮对话训练是本项目的另一重要功能，它能够训练模型记住对话历史上下文的能力。在多轮对话场景中，训练数据采用对话历史（conversations）格式，包含多个角色（role）和内容（content）对，分别表示用户（user）和助手（assistant）之间的多轮交互。通过这种训练方式，模型能够学习理解对话的前后文关系，生成更加连贯和准确的回复。多轮对话训练对于构建智能客服、聊天机器人、对话助手等应用场景至关重要。

### 自动效果验证

项目集成了 ROUGE（Recall-Oriented Understudy for Gisting Evaluation）评分系统，能够自动评估微调后模型的生成效果。ROUGE 是一组用于评估文本摘要和生成任务的标准指标，包括 ROUGE-1、ROUGE-2、ROUGE-L 等多种变体。在本项目中，主要使用 ROUGE-1 和 ROUGE-L 指标来衡量模型生成回复与参考答案之间的词汇重叠程度和最长公共子序列匹配程度。通过自动化的评估流程，用户可以客观地了解模型微调的效果，并据此调整训练参数或数据集。

### 计算资源管理

项目在训练脚本中集成了计算节点的自动申请和释放功能。在提交训练任务时，脚本会自动向计算集群申请所需的 GPU 或 DCU 节点资源，并配置合理的 CPU 核心数和内存大小，确保训练过程的稳定性。当训练任务完成后，脚本会自动释放所申请的计算节点，避免资源浪费和额外的计费。用户也可以随时通过命令行手动释放节点，提供了灵活的资源管理能力。

## 快速开始

本节将介绍如何快速上手使用本项目进行模型微调。我们假设用户已经具备基本的 Linux 命令行操作经验，并且对 Python 环境有一定的了解。

### 环境准备

在开始之前，需要确保计算环境中已安装 Python 3.8 或更高版本，以及必要的依赖包。可以通过以下命令安装项目所需的 Python 依赖：

```bash
pip3 install torch transformers datasets peft accelerate sentencepiece trl huggingface-hub evaluate rouge-score
```

需要注意的是，如果计划使用 GPU 进行训练，还需要确保 CUDA 环境已正确配置。如果计划使用 DCU 进行训练，则需要加载对应的 DTK 驱动模块。具体的驱动安装和配置方法请参阅 case001 目录下的 gpu.md 和 dcu.md 文档。

另外，由于模型文件和训练数据集通常较大，建议确保有足够的磁盘空间用于存储模型权重、中间检查点和训练结果。通常情况下，Llama3.1-8B-Instruct 模型需要约 16GB 的磁盘空间，训练过程中产生的检查点文件也会占用相当的存储资源。

### 配置模型路径

在运行训练脚本之前，需要确认模型文件的存放路径。当前项目配置中使用的是 `/public/models/Llama3.1-8B-Instruct` 作为默认的模型路径。如果模型文件存放在其他位置，需要修改脚本中的 MODEL_PATH 变量，将其指向正确的模型目录。

模型目录中应包含以下关键文件：config.json（模型配置文件）、tokenizer.json（分词器配置）、tokenizer.model 或 tokenizer_config.json（分词器模型文件）、以及 pytorch_model.bin 或 model.safetensors（模型权重文件）。如果模型文件不完整或路径不正确，训练脚本将无法正常加载模型。

### 选择训练模式

根据可用的硬件资源，用户需要选择相应的训练脚本。如果计算节点上配置了 NVIDIA GPU，应使用 GPU 训练模式；如果使用国产 DCU 加速卡，应使用 DCU 训练模式；如果既没有 GPU 也没有 DCU，则只能使用 CPU 训练模式作为兜底方案。

以下是不同训练模式的对比表格：

| 训练模式 | 适用硬件 | 推荐显存 | 训练速度 | 脚本文件 |
|---------|---------|---------|---------|---------|
| GPU 训练 | NVIDIA GPU | 16GB 以上 | 快 | case001/training_gpu.sh |
| DCU 训练 | 国产 DCU 加速卡 | 16GB 以上 | 快 | case001/training_gpu.sh |
| CPU 训练 | 仅 CPU | 15GB 以上内存 | 慢 | case001/training_cpu.sh |

需要特别说明的是，GPU 训练脚本和 DCU 训练脚本在功能上是通用的，通过修改脚本中的资源申请参数（gres 类型）即可适配不同的硬件平台。training_gpu.sh 脚本默认使用 `--gres=gpu:1` 申请 NVIDIA GPU 资源，training_cpu.sh 脚本则使用 `--gres=dcu:1` 申请 DCU 资源。

### 执行训练

确认环境和配置正确后，可以通过以下命令启动训练：

对于 GPU 或 DCU 训练，进入 case001 目录并运行训练脚本：

```bash
cd case001
chmod +x training_gpu.sh
./training_gpu.sh
```

对于 CPU 训练（兜底方案）：

```bash
cd case001
chmod +x training_cpu.sh
./training_cpu.sh
```

训练脚本会自动完成以下步骤：申请计算节点、配置训练环境、加载模型和数据集、执行训练、验证模型效果、释放计算节点。训练过程中会输出详细的日志信息，用户可以实时监控训练进度和各项指标。

训练完成后，微调后的模型会保存在指定的输出目录中（默认为 `./llama3.1_64g_finetune_results` 或 `./llama3.1_cpu_final`），包含模型权重文件、分词器文件和配置文件。用户可以使用保存的模型进行后续的推理部署。

## 训练数据格式

正确的数据格式是保证训练顺利进行的必要条件。本项目支持两种数据格式，分别对应单轮对话训练和多轮对话训练。

### 单轮对话数据格式

单轮对话数据采用列表格式，每个元素是一个包含 instruction 和 response 两个字段的字典。instruction 字段存放用户输入的指令或问题，response 字段存放期望的回复内容。以下是一个典型的单轮对话数据集示例：

```python
single_train = [
    {
        "instruction": "用 Python 实现快速排序算法",
        "response": "def quicksort(arr):\n    if len(arr) <= 1:\n        return arr\n    pivot = arr[len(arr) // 2]\n    left = [x for x in arr if x < pivot]\n    middle = [x for x in arr if x == pivot]\n    right = [x for x in arr if x > pivot]\n    return quicksort(left) + middle + quicksort(right)"
    },
    {
        "instruction": "解释什么是机器学习",
        "response": "机器学习是人工智能的一个分支，它使计算机能够从数据中学习并改进性能，而无需被明确编程。其核心思想是通过算法解析数据，从中发现模式，并利用这些模式进行预测或决策。"
    },
    {
        "instruction": "推荐五本编程入门书籍",
        "response": "1.《Python编程：从入门到实践》\n2.《JavaScript高级程序设计》\n3.《算法导论》\n4.《代码整洁之道》\n5.《深入理解计算机系统》"
    }
]
```

在实际应用中，用户可以根据自己的业务需求准备类似的训练数据。每个 instruction-response 对应该是一个独立的训练样本，样本数量越多，模型学习到的知识越丰富，但相应的训练时间也会增加。建议初学者先使用小规模数据集（10-50 条）进行调试，确认流程无误后再扩大数据规模。

### 多轮对话数据格式

多轮对话数据同样采用列表格式，但每个元素的结构更为复杂。conversations 字段是一个列表，包含多轮对话中的所有消息，每条消息有 role 字段（表示发送者角色，取值为 user 或 assistant）和 content 字段（表示消息内容）。以下是典型的多轮对话数据集示例：

```python
multi_train = [
    {
        "conversations": [
            {"role": "user", "content": "我想学习 Python 编程，应该从哪里开始？"},
            {"role": "assistant", "content": "建议从基础语法开始，学习变量、数据类型、条件语句和循环等核心概念。可以先找一本入门教材或在线教程。"},
            {"role": "user", "content": "有没有推荐的入门教材？"},
            {"role": "assistant", "content": "《Python编程：从入门到实践》是一本非常经典的入门书籍，内容通俗易懂，配有丰富的实战项目。"},
            {"role": "user", "content": "学完基础后应该学什么？"},
            {"role": "assistant", "content": "学完基础后可以学习函数、模块、面向对象编程等进阶内容，然后尝试做一些小项目来巩固所学知识。"}
        ]
    }
]
```

多轮对话训练能够使模型理解对话的上下文关系，生成更加连贯和准确的回复。在准备多轮对话数据时，需要注意保持对话逻辑的一致性，确保助手（assistant）的回复在上下文中是合理且正确的。

### 数据预处理

训练脚本会自动对输入数据进行预处理，包括文本格式化、tokenization、padding 和标签生成等步骤。用户只需按照上述格式准备原始数据，脚本会将其转换为模型可接受的输入格式。预处理过程中会使用模型配套的分词器（Tokenizer），确保输入文本被正确地切分为词元（token）序列。

如果需要自定义数据预处理逻辑，可以修改脚本中的 preprocess_data 或 format_data 函数。该函数接收原始数据样本作为输入，返回包含 input_ids、attention_mask 和 labels 的字典，这些字段将作为模型的直接输入。

## 核心配置参数

微调效果很大程度上取决于训练参数的合理配置。以下是本项目中最关键的一些参数及其推荐值，用户可以根据实际情况进行调整。

### 批次大小

per_device_train_batch_size 参数控制每个 GPU 或 CPU 设备每步训练处理的样本数量。较大的批次大小能够提高 GPU 利用率和训练稳定性，但会增加显存占用。对于 64GB 显存的 GPU，推荐设置为 8；对于 16GB 显存的 GPU，通常设置为 2-4 即可。如果显存不足，可以适当减小批次大小，或启用梯度累积（gradient_accumulation_steps）来模拟更大的有效批次。

### 学习率

learning_rate 参数控制模型参数更新的步长。较高的学习率能够加快收敛速度，但可能导致训练不稳定；较低的学习率训练更稳定，但收敛速度较慢。对于 LoRA 微调，推荐使用 2e-4（0.0002）作为初始学习率。如果训练过程中出现 loss 振荡或发散，可以尝试降低学习率至 1e-4 或 5e-5。

### 训练轮数

num_train_epochs 参数控制完整遍历训练数据集的次数。较少的训练轮数可能导致欠拟合，模型未能充分学习数据中的知识；较多的训练轮数可能导致过拟合，模型在训练数据上表现很好但泛化能力下降。通常情况下，2-3 个训练轮数能够取得较好的平衡。对于数据量较大的场景，可以适当减少轮数；对于数据量较小的场景，可以增加轮数以确保模型充分学习。

### LoRA 参数

LoRA 相关的参数包括 r（秩）、lora_alpha（缩放系数）、lora_dropout（dropout 概率）和 target_modules（目标模块列表）。

r 参数决定了低秩矩阵的维度，较小的值（如 4-8）计算效率高但表达能力有限，较大的值（如 16-32）表达能力更强但计算开销更大。lora_alpha 参数用于缩放 LoRA 输出的贡献，通常设置为 r 的两倍。lora_dropout 参数用于防止过拟合，推荐值为 0.05-0.1。target_modules 参数指定在哪些模块应用 LoRA 适配器，对于因果语言模型，通常选择 q_proj、k_proj、v_proj 和 o_proj 这四个注意力相关模块。

### 精度设置

fp16 和 bf16 参数控制训练使用的数值精度。fp16（半精度浮点数）能够显著减少显存占用和加快训练速度，但在某些情况下可能导致数值不稳定。bf16（Brain Float 16）是另一种低精度格式，动态范围更大，数值稳定性更好。如果 GPU 支持 bf16，推荐使用 bf16=True；否则使用 fp16=True。对于 CPU 训练，这两个参数应设置为 False。

## 硬件配置要求

不同的训练模式对硬件有不同的要求，用户需要根据实际可用的计算资源选择合适的训练模式。

### GPU 训练环境要求

对于 NVIDIA GPU 训练模式，推荐的硬件配置如下：显卡显存应不少于 16GB，更好的选择是 24GB 或 64GB 显存的显卡；系统内存应不少于 32GB；CUDA 版本应为 11.8 或更高版本。显存大小直接影响可用的批次大小和模型配置的灵活度，64GB 显存的显卡能够使用更大的批次大小和更长的序列长度，训练效率更高。

### DCU 训练环境要求

对于国产 DCU 加速卡训练模式，推荐的硬件配置如下：DCU 显存应不少于 16GB，推荐 64GB 显存的型号；系统内存应不少于 32GB；需要加载 DTK 25.04 或更高版本的驱动模块。DCU 是国产异构加速卡，需要使用专门的 DTK（DCU Toolkit）进行开发，训练时需要安装 torch-dcu 版本的 PyTorch，而非标准的 CUDA 版本。

### CPU 训练环境要求

对于 CPU 训练模式，硬件要求相对较低，但训练速度会明显变慢。推荐的系统内存应不少于 15GB，更大的内存能够支持更大的批次和更长的序列。由于 CPU 训练仅作为兜底方案，不建议用于生产环境的大规模训练，仅用于验证数据流程和调试配置。

## 技术栈说明

本项目基于以下技术和框架构建：

模型层面使用了 Meta 公司的 Llama3.1-8B-Instruct 模型，这是 Llama 3.1 系列中的 instruction-tuned 版本，经过指令跟随能力的专项优化，在对话和任务执行方面表现出色。分词器（Tokenizer）使用了与模型配套的 SentencePiece 分词器，能够有效处理多种语言和特殊字符。

微调方法采用了 LoRA（Low-Rank Adaptation）技术，这是一种参数高效微调方法，通过在模型中添加低秩矩阵来实现能力的定向提升。与全参数微调相比，LoRA 只需要训练极少量的参数（通常不到 1%），大大降低了显存需求和训练时间。

训练框架基于 Hugging Face 的 Transformers 库和 PEFT（Parameter-Efficient Fine-Tuning）库。Transformers 提供了丰富的预训练模型和便捷的训练接口，PEFT 则实现了多种高效微调方法（包括 LoRA）的统一封装。评估指标使用了 ROUGE 系列评分，这是自然语言处理领域评估文本生成质量的常用指标。

## 注意事项

在正式使用本项目进行生产环境的模型训练之前，有以下几点需要特别注意：

第一，关于模型路径的配置。训练脚本中使用的模型路径 `/public/models/Llama3.1-8B-Instruct` 是示例路径，用户需要根据自己的实际情况修改为正确的模型存放位置。如果模型路径不正确，脚本将无法加载模型。在运行训练脚本之前，建议先确认模型文件是否存在且完整。

第二，关于训练参数的调整。文档中提供的参数推荐值是基于典型硬件配置的默认值，实际使用时需要根据具体的硬件条件和数据特点进行调整。如果训练过程中出现显存不足的问题，应首先减小批次大小；如果训练 loss 出现振荡，可以适当降低学习率。

第三，关于计算资源的释放。训练脚本在任务完成后会自动释放所申请的计算节点，但在某些异常情况下（如脚本被强制中断），节点可能未能正确释放。如果发现计算节点未被释放，可以使用 `scancel` 命令手动释放，避免产生额外的资源费用。

第四，关于 DCU 环境的特殊要求。使用 DCU 加速卡时，需要确保已正确加载 DTK 驱动模块，并且安装的是 torch-dcu 版本的 PyTorch，而非标准的 CUDA 版本。如果环境配置不正确，脚本将无法正常运行。

第五，关于数据质量的保证。模型微调的效果很大程度上取决于训练数据的质量。建议确保训练数据中指令（instruction）和回复（response）的对应关系正确，避免出现误导性的样本。同时，数据量也不宜过少，否则模型难以学习到足够的知识。
