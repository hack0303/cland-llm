# H-01 AI 修图产线 · 操作手册

> 适用：#130 H-01（老照片修复 / 黑白上色 / 高清增强 / 电商主图）。**产线已落地**（#179 跑通、#219 上架、#224 素材）。
> 配套：上架《上架说明-v1》《客服话术-v1》《定价战术》· 流转《接单入口与流转协议-v1》（均在 `cland-op/docs/operations/AI修图/`）。

## 0. 能力与交付物

| 服务 | mode | 交付物 | **SDXL 依赖** | 备注 |
|---|---|---|---|---|
| 老照片修复 | `repair` | 去噪/去划痕/清晰化后的**黑白**成品（+ before/after 对比图） | **是** | 保持黑白；给黑白照**上色**用 `colorize` |
| 黑白上色 | `colorize` | 自然彩色成品（+ 对比图） | **否**（`--colorizer ddcolor`）| **必须用 DDColor 链路**（见 §3）；默认 sdxl 模式**是** |
| 高清增强 | `upscale` | 放大清晰成品（+ 对比图） | **否** | RealESRGAN x4 |
| 电商主图 | `product` | 纯白底商品图（+ 对比图） | **是** | 去背白底 |

> **SDXL 说明（C4）**：产线 SDXL 是 **in-process diffusers**（`models/stable-diffusion-xl-base-1.0-fp16`，进程内加载），**不是 `:10331` 服务**——`:10331` 暂停**不影响**产线。**暂停期可交付 = 上色 + 高清**（不依赖 SDXL）；repair/product 依赖 SDXL。

- **SLA**：标准 24h / 加急 2h（视档期）；**瓶颈=人工质检**。
- **定价**：严格引《定价战术 v0》（体验 ¥19 / 标准 ¥49 / 精品 ¥129；新客 ¥9.9 限 1 张；电商主图 ¥59/张·5 张 ¥199）——**本手册不另立价**。
- 产线仓库：`/mnt/data/ai_workspace/cland-llm`。

## 2. 每单标准作业（必做：**脱敏命名 + 独立目录**）

> **隐私合规（C1/C2）**：`case` 默认取**输入文件名** → 直接用真实客户姓名会**把姓名写进输出路径**。**每单必须先脱敏 + 独立目录**，勿共享 `$CR` 混放。

```bash
cd /mnt/data/ai_workspace/cland-llm
ORDER="S901_kehu"                                    # 单号_脱敏代号（勿用真名）
DST="/mnt/data/ai_workspace/outputs/orders/$ORDER"    # 每单独立输出目录
mkdir -p "$DST/in"
cp "<客户原图>" "$DST/in/$ORDER.jpg"                   # 脱敏：文件名 = 单号_代号
python3 inference/photo/retouch.py --input "$DST/in/$ORDER.jpg" --output "$DST" --mode repair --strength 0.3 --damage-fix
```
输出：`$DST/$ORDER/{before.png,after.png,compare.png,meta.json}`（`case=$ORDER`，路径不含真名）。

## 2.1 四模式命令参考

```bash
O="S901_kehu"; DST="/mnt/data/ai_workspace/outputs/orders/$O"; IN="$DST/in/$O.jpg"
# ① 老照片修复（黑白，依赖 SDXL）
python3 inference/photo/retouch.py --input "$IN" --output "$DST" --mode repair --strength 0.3 --damage-fix
# ② 黑白上色（DDColor 链路，推荐；不依赖 SDXL）
python3 inference/photo/retouch.py --input "$IN" --output "$DST" --mode colorize --colorizer ddcolor
# ③ 高清增强（不依赖 SDXL）
python3 inference/photo/retouch.py --input "$IN" --output "$DST" --mode upscale
# ④ 电商主图（白底，依赖 SDXL）
python3 inference/photo/retouch.py --input "$IN" --output "$DST" --mode product
```

> ⚠️ **上色务必 `--colorizer ddcolor`**：SDXL 老链路 `strength=0.80` 会在**手臂/衣物产生蓝块串色**（#225 已证）；DDColor 干净且快（~0.3s/张）。

## 3. 模式与参数速查

| 参数 | 取值 | 说明 |
|---|---|---|
| `--mode` | `repair`/`upscale`/`colorize`/`product` | 见 §0 |
| `--colorizer` | `sdxl`(默认)/`ddcolor` | **colorize 用 `ddcolor`** |
| `--strength` | repair 0.25–0.35 · colorize(DDColor 忽略) | img2img 强度；repair 低更保结构 |
| `--damage-fix` | 开关 | repair 预处理：去划痕/白斑/霉点（形态学+inpaint） |
| `--skin-fix` | 开关（默认关） | colorize 后处理：脸/手臂肤色色偏修复；DDColor 链路一般**不需要** |
| `--work-res/--max-side` | 1024/2048 | 工作分辨率/输出长边 |
| `--batch` | 1 | 同模式组批（P40 无 Tensor Core，批>1 收益低） |

## 4. 批量（manifest）

多个客户单/多张一次跑，用 `cases.json`：

```json
[
  {"name":"S001_repair","input":"/mnt/data/ai_workspace/outputs/orders/S001_kehu/in/S001_kehu.jpg","mode":"repair","strength":0.3,"damage_fix":true},
  {"name":"S001_color","input":"/mnt/data/ai_workspace/outputs/orders/S001_kehu/in/S001_kehu.jpg","mode":"colorize"}
]
```
```bash
python3 inference/photo/retouch.py --manifest cases.json --output /mnt/data/ai_workspace/outputs/orders/S001_kehu --colorizer ddcolor
```
> **脱敏（C1/C2）**：manifest 的 `name` = 输出目录名、`input` 路径也应**脱敏**（单号_代号），**勿用真实姓名**；每单一个 `--output` 目录。
> `colorize` 案例自动走 DDColor（`--colorizer` 全局；上色用 DDColor）。产出后拉 `run.json` 看总体耗时/失败率。

## 5. 质检（交付前必做）

逐单核对 `compare.png` + `after.png`：
- [ ] **修复(repair)**：噪声/划痕/霉点明显减少；无涂抹失真；未把黑白上色。
- [ ] **上色(colorize)**：肤色自然；**脸/手臂无蓝块、无灰块**；衣物颜色位置正确（非错位）。
- [ ] **高清(upscale)**：清晰度提升、无虚假细节；边缘不糊。
- [ ] **主图(product)**：背景纯白无阴影；商品居中、色准。
- [ ] 对比图完整（before/after 并排）、尺寸合理。
- 判定不通过 → 调参重出（repair 调 `strength`；上色确认走了 DDColor；主图调 `--mode product`）。
- **回填质检记录（C5）**：逐单写入 `cland-op/docs/operations/AI修图/质检记录-试运营.csv`（单号 / 项目 / 通过与否 / 备注）——未回填不算质检完成。

## 6. 交付

- **成品**：`after.png`（高清）+ `compare.png`（前后对比）。
- **命名**：脱敏客户代号（勿用真实姓名）；不出现模型/管线/内部路径/工单（**去技术化**）。
- **交付说明**：套 `cland-op/docs/operations/AI修图/交付说明模板.txt`（含 **AI 技术制作明示**、隐私声明、效果免责）。
- **隐私（C3，必做）**：客户原图**仅本单使用**；**交付后删除原件与工作目录**，操作步骤：
  ```bash
  # 交付确认后执行（删除本单输入原件与中间产物；建议保留 before/after 交付件至售后窗结束）
  rm -rf "/mnt/data/ai_workspace/outputs/orders/$ORDER/in"      # 删客户原件
  # 售后窗结束再删整单：rm -rf "/mnt/data/ai_workspace/outputs/orders/$ORDER"
  ```
  删除后在 `订单台账-试运营.csv` 备注「已删除原件 YYYY-MM-DD HH:MM」；**客户原图不入公开样例**。

## 8. 常见问题（FAQ / 排障）

| 现象 | 原因 | 处理 |
|---|---|---|
| 上色手臂/衣物**蓝块/错位** | 走了 SDXL 老链路(strength .80) | 加 `--colorizer ddcolor` 重出 |
| 上色**偏灰/色淡** | SDXL 低强度 | 改用 DDColor（色度更足） |
| 修复后**仍有划痕** | 未开去损伤 | repair 加 `--damage-fix`；必要时降 `--strength` 重出 |
| 修复把**人脸涂糊** | strength 过高 | 降 `--strength`（0.25–0.3） |
| 商品**背景不纯白** | 未走 product / 阴影 | 用 `--mode product`；必要时裁切 |
| **加载模型报错/找不到 DDColor** | 权重路径 | 确认 `models/ddcolor/ddcolor_modelscope.pt`；或用 `DDCOLOR_CKPT` 指定 |
| 显存不足/OOM | 与他服务同卡 | 换空闲卡 `CUDA_VISIBLE_DEVICES`；降 `--max-side` |
| 图片带**文字/水印/证件** | 不接清单 | 按《上架说明》不接（涉隐私/合规） |
| **同一张卡跑多个任务变慢/卡** | 并发/负载（C6） | 产线为**单卡串行**：**勿并行提交多单**；首次加载冷启（prep 137s vs 暖跑 ~16s）属正常；避开与常驻服务高峰（必要时 `CUDA_VISIBLE_DEVICES` 指定空闲卡、降 `--max-side`）。**不要为跑单擅自停/起常驻推理服务**。 |
